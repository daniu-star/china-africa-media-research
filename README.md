# 非洲媒体、中非命运共同体与情感传导研究

论文及研究材料的私有工作仓库，用于后续论文修改、Agent 遍历、克隆与分析。

论文基准版本：**修3 发展的情感转译：非洲媒体对中非命运共同体的情感传导路径与认同建构**。原文见 `paper/`，同目录 `manuscript.txt` 提供可检索的段落和表格文本。文本导出不包含图片内容，版式以 Word 原文为准。本仓库只收录用户指定的修3版本，不代表工作目录中其他修订稿。

## 快速使用

```bash
git clone https://github.com/daniu-star/china-africa-media-research.git
cd china-africa-media-research
python tools/restore_data.py --only 清洗数据
python tools/restore_data.py --only 最终优化结果
```

完整恢复全部研究文件：

```bash
python tools/restore_data.py
```

恢复路径默认为 `restored/demo/`，可用 `--output PATH` 指定新目录。工具仅依赖 Python 3.9+ 标准库；自动核验压缩分卷和恢复文件的 SHA-256，拒绝覆盖内容不同的文件。分卷是连续的 gzip 数据流，必须全部保留；`--only` 减少恢复的磁盘空间，但仍顺序读取压缩流。完整恢复前请预留至少 20 GB 可用空间。

## 从哪里开始

| 位置 | 用途 |
|---|---|
| `AGENTS.md` | 后续 Agent 的阅读顺序、数据边界和运行注意事项 |
| `paper/` | 指定论文 Word 原文及文本索引 |
| `demo/` | 可直接浏览的脚本、报告、词典说明及体积适中的分析产物 |
| `metadata/manifest.json` | 完整文件路径、原始体量、SHA-256、重复文件映射、排除和代码脱敏记录 |
| `metadata/file_inventory.tsv` | 可直接搜索或导入表格的完整文件索引 |
| `metadata/verification.md` | 此次整理的体量和校验记录 |
| `metadata/data_guide.md` | 主要数据字段和分析目录导览 |
| `archive/` | 所有收录文件的无损压缩分卷，每卷不超过 40 MiB |
| `tools/restore_data.py` | 恢复、选择目录和完整性检查 |
| `tools/verify_archive.py` | 不解压到磁盘，逐文件校验整个归档 |

`demo/` 是快速浏览副本，并非完整数据目录。执行分析建议使用恢复后的完整目录，以保留脚本依赖的相对位置。相同内容在压缩包内只存储一次，恢复工具会根据清单重建所有原路径。

## 数据与分析的边界

按研究者说明，`清洗数据/清洗数据.json` 是本项目的**原始数据入口**；文件夹名称不代表已经完成论文分析样本的核验。`最终优化结果/data_with_5_regions.csv` 是带有派生指标与区域信息的历史分析表。其余分析目录和不同版本脚本是既有研究过程材料，不能仅根据“最终”“优化”等名称判断其有效性。

保留的 `非洲_诊断输出/audit_report.md` 是已有自动诊断，不是此次上传重新完成的实证核验。该报告提示原始数据识别结构与论文报告样本数不一致，且原始结构缺少部分模型变量。后续修改应首先核对原始记录、筛选规则、分析样本与论文数字的对应关系。上传成功不等同于验证论文结论或重现模型。

## 上传处理说明

- 原始文件保持在原工作目录，本仓库是独立的整理副本。
- 不上传 `.env`、代理凭据文件、运行日志、本地依赖、缓存和编辑器目录；具体见清单。
- 对脚本中检出的硬编码密钥及认证代理地址替换为占位文本，文件路径列在清单中。需要相关服务时，请在本机另行配置凭据。
- 数据文件保持内容不变；文件级 SHA-256 和重复映射用于核验恢复结果。
- 大文件采用标准库可恢复的压缩分卷，不依赖 Git LFS，也不需要额外的大文件存储服务。不要在 GitHub 网页中手动将恢复后的大文件再次上传。
- 研究材料不附加公开再分发许可；新闻文本的权利归原权利人。仓库用于研究者的私有研究工作。

## 依赖与复现

历史 `demo/requirements.txt` 主要面向爬虫，未必覆盖论文分析所用的全部包；分析脚本还可能引用 pandas、SciPy、statsmodels、seaborn、transformers 等。请先阅读所需脚本的导入和文件路径，在独立环境中安装相应依赖。不要直接批量运行所有脚本：部分脚本启动爬虫、连接外部服务或覆盖数据。

以后修改时，优先提交脚本、文档和小型结果。若原始大文件确有更新，需重新生成归档与清单并核验；不要只修改清单或只替换某一个分卷。
